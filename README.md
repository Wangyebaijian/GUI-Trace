# UI-Trace-Effeciency

GUI-Tracelite 的本机可视化研究原型：保留关键节点原图，把其余历史截图按时序压入固定画布，并始终保留清晰的当前屏幕。

## 启动

环境要求：Node.js 22 或更新版本、npm、Google Chrome。自由桌面任务另需 macOS 和 Xcode Command Line Tools（`xcode-select --install`）。

在本目录执行：

```sh
npm ci
npm run build
npm start
```

打开 `http://127.0.0.1:4317`。展演入口为 `http://127.0.0.1:4317/?present=1`，将实时画面、关键记忆和轨迹时间线放在一屏中。服务只监听本机回环地址。首次运行前请完成上述依赖安装。

## 两种执行方式

**长时序演示**无需模型密钥。点击“启动任务”，系统启动独立的本机 Chrome 工作区，实际操作发布计划、笔记与提醒。28 个阶段执行窗口包含约 126 秒的可视化观察间隔，完整运行约 2–3 分钟；这是可复现实验节奏，不是智能体速度测试。

任务先设定原始日期、09:30、演示室 A 和 6800 元预算，并接收本次运行唯一的恢复口令；随后改为次日 14:00、演示室 B 和 5200 元，删除原始笔记；再只恢复原日期、重建提前 24 小时的提醒，最后从保留的早期记忆恢复预算与口令。8 项验收检查直接读取任务应用的最终状态。每次运行口令不同。

演示中的 GUI 动作是预编排的 Playwright 操作。截图、压缩画布、选择评分、字节统计和验收结果实时生成；恢复使用被保留关键帧的同期 DOM 观察记录。这一模式没有调用视觉模型，不表示端到端自主智能体成绩，也不是 OSWorld 官方测评。

**自由任务**使用真实本机桌面和你配置的视觉模型。打开右上角设置，填写 OpenAI 兼容接口的 Base URL（通常包含 `/v1`）、模型名及密钥；选择“自由任务”，输入例如“打开计算器，计算 128 × 64，再打开系统设置并进入外观页面，仅查看当前设置”。每步把关键原图、历史画布、当前屏幕和动作历史交给模型，再执行其返回的本机动作。UI-TARS 模型名走官方动作语法解析，其他视觉模型走 JSON 动作协议。

API Key 只存于本次服务进程的内存中，重启需重新填写，不写入日志或运行导出。运行自由任务时，选定历史截图和当前桌面将发往你填写的接口。设置页保存不触发模型请求。本机需开启辅助功能与屏幕录制权限；当前应用只支持主显示器。

暂停会等待正在进行的单个操作结束；停止会中止后续动作及未完成的模型请求。请在执行期间留出桌面控制。自由任务最多 60 步，模型返回 `done` 只表示模型自报完成，界面会标注“结果待核对”。

## Recent5 对比实验

点击“记忆对比实验”，系统用**相同随机种子、相同初始口令、相同步骤和相同验收规则**，依次完成 GUI-Tracelite 与 Recent5 两次真实 GUI 运行，总计约 5 分钟。

|策略|最多输入图像|早期历史如何处理|
|---|---|---|
|GUI-Tracelite|3 张关键原图＋1 张画布＋当前图，共 5 张|关键锚点保真，普通历史按时序进入画布|
|Recent5|最近 5 张原图，包含当前图|直接丢出窗口，不做摘要、关键帧保留或画布压缩|

第 1 步出现本轮随机口令，随后保存为笔记，第 15 步删除原始笔记，第 23 步要求恢复。口令不写入任务指令，也不额外提供文字摘要。每个策略的恢复函数只能读取**它实际保留的图像对应观察**，无法查询完整审计记录或另一策略的答案；Recent5 在窗口内能找到口令时正常成功，单元测试覆盖这一正例，不是代码按策略名写死失败。

原预算 6800 元已写在任务指令里，因此两组都允许从指令恢复预算。对比的关键检查仅是未知随机口令能否找回，不能把已知预算也算作遗忘。未找到口令时会在真实应用里写明缺失，继续其余步骤，再由最终状态验收器判断是否通过。

界面展示两组逐项检查、恢复命中来源、检索时的可用帧、图像用量及完整审计轨迹。Recent5 的完整时间线只是审计，不会重新加入决策记忆。对比数据保存为 `artifacts/对比实验.json`，点击“逐项验收对照”查看。

**这是单任务受控记忆消融，不是视觉模型自主执行成功率实验。** GUI 操作序列预编排，信息恢复用保留帧的同期 DOM 观察检索，排除了 OCR、模型推理和动作生成的随机性。它检验在这项长依赖条件下信息是否还可访问，不能据此声称所有模型、所有 GUI 任务上都更好。已配置模型的自由任务接口同样支持 `policy: "recent5"`，但模型可能从自己的文字历史记住口令，端到端结论需要另行实测。

## 算法与可视化

实现路径为 `server/memory.mjs`：

1. 当前图像单独保留，不进入历史画布。
2. 从已发生的历史中选取最多 3 张关键原图。工程规则综合任务实体、首次原始约束、时间冲突、删除、恢复、提交状态、缩略图变化与阶段覆盖；重要的早期锚点被保护。
3. 非关键历史按先后顺序拼入 1536 × 864 的 WebP 画布。帧号标签放在图像外，不把旧画布当作可点击的当前屏幕。
4. 模型接收顺序：历史画布 → 关键原图 → 当前屏幕。动作文字历史继续保留。

这是论文关键节点保留＋视觉画布压缩结构的工程落地，在线选择器是新增的可解释启发式规则，不是论文已训练或验证的选择模型。演示事件来自任务执行器的已发生动作和可见通知；桌面模式事件来自前一步模型的动作说明。没有使用未来帧或后续验收答案来选帧。

界面显示：真实截图与逐帧回看、动态画布、关键原图及评分理由、动作日志、跨阶段任务链、最终约束验收。**图像字节变化是实际测量；视觉词元仅按 `85 + 170 × ceil(width/512) × ceil(height/512)` 估算**，不是模型账单或统一的跨模型计费口径。少量帧时记忆编码可能膨胀，负百分比表示增大。文本上下文不会因为图像压缩自动变成常量。

## 开源来源

- [ByteDance UI-TARS Desktop](https://github.com/bytedance/UI-TARS-desktop)：实际集成官方 `@ui-tars/action-parser@1.2.3`，处理 UI-TARS 动作文本、坐标和键盘动作。不是完整 Electron 桌面应用的分叉；依赖由 npm 安装，版本由 lockfile 固定；许可证副本位于 `third-party/UI-TARS-LICENSE`。
- [OSWorld-V2](https://github.com/xlang-ai/OSWorld-V2)：参考其长时序、多步骤、状态变化的任务方向。本项目演示是专门为 macOS 本机环境构造的任务，不是 Ubuntu 虚拟机中的官方 OSWorld 任务或官方分数。
- Playwright：本机浏览器真实 GUI 演示；Sharp：图像取样、缩放、拼图与编码；React/Vite：可视化界面。

## 运行记录与验证

每次运行保存到 `runs/<运行编号>/`：原始 PNG、每一步生成的 WebP 画布及 `run.json`。界面右上角可以导出不含密钥的 JSON 记录。暂停或停止不会删除已形成的证据。

精简源码仓库不附录像、截图或历史运行记录。运行演示会在本机生成截图与画布；对比结果会写入 `artifacts/对比实验.json`，这些生成文件均被 Git 忽略。

```sh
npm test
npm run build
npm audit
```

自动检查覆盖图像分区不遗漏、不重复，当前图最后输入，真实图像尺寸与字节统计，删除后的锚点恢复，UI-TARS 解析、坐标限制、接口图像 MIME 与返回 usage。真实桌面模型效果取决于所接模型；尚未用用户的真实接口完成验证。

目录：`src/` 界面，`server/index.mjs` 运行调度，`server/demo.mjs` 时序任务，`server/workbench.html` 被操作的应用，`server/desktop.mjs` 模型与本机执行，`server/memory.mjs` 视觉记忆，`test/` 验证。
